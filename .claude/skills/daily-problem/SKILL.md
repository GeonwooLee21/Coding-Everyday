# Daily C++ 자료구조 문제 생성

`daily-learning/cpp/`에 오늘의 자료구조 학습 문제를 생성하는 스킬이다.
모든 규칙의 최종 출처는 프로젝트 루트의 `CLAUDE.md`다. 이 파일과 충돌하면
`CLAUDE.md`를 우선한다.

## 실행 절차 (Steps)

### 1. 현재 상태 파악

- `CLAUDE.md`의 "커리큘럼 순서"에서 **가장 위의 미완료(`[ ]`) 항목**을 찾는다.
  이것이 현재 진행 중인 주제다.
- `daily-learning/cpp/problems/`와 `markdown/`의 기존 `DayNN_*` 파일들을 확인해
  - 가장 큰 `NN` 다음의 2자리 번호를 정한다 (예: `Day03_*`이 최신이면 다음은 `Day04_*`).
    파일이 하나도 없으면 **오늘이 `Day01`이다.**
  - 현재 주제에서 지금까지 어떤 변형(`array`/`linked`/`applied` 등)을 다뤘는지
    기존 파일명·내용으로 파악한다.

> ⚠️ **문서와 실제 상태가 다를 때**: 이 파일이나 `CLAUDE.md`에 적힌 규칙이
> 실제 파일 구조·내용과 어긋나면, 임의로 추측해서 진행하지 말고
> 먼저 사용자에게 어떻게 처리할지 물어본다. 답을 받으면, 재발 방지를 위해
> 해당 규칙을 `CLAUDE.md`/`SKILL.md`에 반영할지도 함께 제안한다.

> ⚠️ 기존 폴더 `01_stack/`·`02_list/`·`03_stack/`은 과거 방식이다.
> 읽어서 진도 참고용으로 쓰되, **수정·이동하지 않는다.**

### 2. 직전 코드 분석 (진도 판단)

- 가장 최근(가장 큰 번호) `problems/DayNN_*.cpp`에서 **사용자가 채운 부분**을 읽는다.
- `CLAUDE.md`의 "진도 판단 규칙"에 따라 판단한다:
  - 아직 현재 주제의 변형이 남았거나, 반복 실수가 보이면
    → **같은 주제**에서 다음 단계(난이도 한 단계 위) 문제를 준비한다.
  - 모든 변형을 다뤘고 기준을 충족한 것 같으면
    → **먼저 사용자에게 다음 주제로 넘어갈지 물어본다.** 승인 전까지 문제를 만들지 않는다.
    → 승인받으면 `CLAUDE.md` 커리큘럼의 해당 항목을 `[x]`로 바꾸고 다음 주제로 넘어간다.
- 직전 코드에서 발견한 반복 실수(연산자, 인덱스 경계, STL 사용 등)가 있으면
  오늘 문제에 그 문법을 다시 노출하는 요소를 넣는다.

> ⚠️ 첫 실행이라 직전 코드가 없으면, 현재 주제의 가장 쉬운 변형(촘촘한 빈칸)으로 시작한다.

### 3. 문제 생성

같은 이름(`DayNN_<topic>_<variant>`)으로 아래 두 파일을 짝지어 생성한다.
포맷 세부사항은 `CLAUDE.md`의 "일일 문제 포맷"을 그대로 따른다.
**새 폴더는 만들지 않는다** — 기존 `problems/`·`markdown/` 폴더 안에 파일만 추가한다.

- `markdown/DayNN_<topic>_<variant>.md`
  — 학습 목표 / 개념 설명 / 미션 / 요구사항(표) / 예제 / 생각해보기 (한·영 병기)
  — 마지막에 `📝 배운 점 / 정리 (My Notes)` 섹션을 **빈 채로** 넣는다.
- `problems/DayNN_<topic>_<variant>.cpp`
  — `// TODO N:` 빈칸 + 하단 테스트 섹션(`main`, 수정 금지)

난이도(빈칸 크기)는 진도 판단 결과에 맞춘다:
- 현재 주제 초반 → 한 줄 단위 빈칸
- 중반 → 함수 단위 빈칸
- 후반 → 메서드 단위 빈칸(시그니처만)

### 4. 마무리 안내

생성 후 사용자에게 다음을 간단히 알린다:
- 오늘의 주제와 변형, 난이도 단계
- 생성된 두 파일 경로
- 컴파일/실행 명령 (레포 루트에서 실행, 실행 파일명은 항상 `out`):
  `g++cpp -std=c++17 -Wall daily-learning/cpp/problems/DayNN_<topic>_<variant>.cpp -o daily-learning/cpp/problems/out && daily-learning/cpp/problems/out`

## 하지 말 것 (Do NOT)

- markdown 파일의 `📝 배운 점 / 정리` 섹션을 채우지 말 것. 빈 채로 둔다.
- `.cpp`에 정답을 노출하지 말 것. TODO는 반드시 비워 둔다.
- 테스트 섹션(`main`)의 검증 로직을 빈칸으로 만들지 말 것.
- 사용자 승인 없이 커리큘럼 항목을 `[x]`로 바꾸지 말 것.
- 하루에 여러 주제를 몰아서 내지 말 것. 하루 한 주제(변형) 원칙.
- 새 폴더를 만들거나 기존 `NN_topic/` 폴더를 수정하지 말 것.
